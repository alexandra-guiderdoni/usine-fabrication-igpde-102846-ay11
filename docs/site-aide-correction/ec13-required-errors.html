#13 Formulaire de contact

Aide à la correction

Observer d'abord le formulaire avant envoi, puis le soumettre vide. Comparer l'état initial et l'état après soumission. Ici, les libellés doivent déjà être compréhensibles : le test porte sur l'obligation, les messages et le guidage après erreur.

L'obligation n'est pas annoncée ou la correction n'est pas accompagnée : perte de contexte, erreurs répétées et abandon.

Les cinq points à vérifier sont :

  • État initial : le formulaire de contact ne doit pas afficher d'erreur avant que l'utilisateur soumette.
  • Prévention : les champs nom, courriel et message ne doivent pas être signalés seulement par une couleur ou un astérisque inexpliqué.
  • Technique : les champs requis doivent porter required ou aria-required selon le cas.
  • Message : après soumission, l'erreur doit nommer le champ concerné et expliquer la correction attendue.
  • Association et parcours : le message d'erreur doit être relié au champ avec aria-describedby et le focus doit accompagner l'utilisateur vers le récapitulatif ou le premier champ en erreur.

Prévenir avant soumission, expliquer après soumission, relier techniquement les erreurs et guider le focus.

Corrections attendues :

  • Indiquer clairement la règle des champs obligatoires avant le formulaire de contact.
  • Ajouter required ou aria-required sur le nom, le courriel et le message.
  • Afficher les erreurs seulement après soumission.
  • Rédiger des messages d'erreur précis et les associer aux champs.
  • Utiliser aria-invalid="true" quand le champ est en erreur et guider le focus vers le récapitulatif.

Contacter le ministère

Utilisez ce formulaire pour poser une question sur l'accessibilité numérique, signaler une difficulté ou demander une orientation vers le bon service. Une réponse est apportée pendant les jours ouvrés.
